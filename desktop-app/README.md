# Wayfinder desktop · 0.2.0 workspace-parity candidate

The newly supplied GitHub Wayfinder design is connected to the existing scoped application backend in the isolated `codex/ui-backend-integration` worktree. This is the I0/I1 implementation candidate, **not** accepted general chat or the complete R1–R7 product.

See [current implementation and test evidence](../docs/wayfinder-desktop-v5/implementation/STATUS.md) for completed changes, exact results, launch instructions and outstanding gates. [FEATURES.json](FEATURES.json) is the authoritative build inclusion declaration, shared by navigation, preload/main and the owned Python helper. Availability still requires current service scope and runtime qualification.

Included: real spaces; scoped current/historical memory and sources; exact reviewed assertion/correction/retraction; explicit selected files/W35; the fixed document-and-memory comparison; runs/audit/reconciliation; runtime/Atlas discovery; one bounded local codex/ branch operation; Google setup status only. The Home conversation input stays disabled until the canonical conversation service is complete.

The Windows folder is `release/win-unpacked/`. Keep it intact. It is unsigned and still needs this checkout, a compatible existing Python environment, configured FalkorDB, cached embeddings and the existing managed Hermes sandbox for model work. Nothing installs/resets those services automatically. `Start.ps1 -Python <absolute existing executable>` selects Python for that launch only. `-Runtime <absolute compatible root>` explicitly selects existing data after quitting; storage ownership remains enforced. Packaged default data is in the stable Electron user-data directory, separate from the development root. No private data is imported or copied automatically.

Verification from `desktop-app`: `npm run check`, `npm test`, `npm run package`, then `node scripts/check-package.mjs` after the prerequisite tier reports. The pinned Electron binary must already be installed in `node_modules/electron/dist`. The test helper from the project root accepts `-ClientOnly`, `-NodeBridge`, `-Neural -Live`, and `-Packaged`; each creates/removes its own disposable database. Set `WAYFINDER_PYTHON` to the existing environment. Browser harnesses use the externally available Playwright package via `WAYFINDER_PLAYWRIGHT_MODULE`; the fixture renderer also accepts `WAYFINDER_CHROME`. No Playwright dependency or system upgrade was added to the application.

Actual packaged tests run hidden with synthetic data, real preload/main/API and isolated stores. Rendered layout tests use visibly labelled synthetic fixtures. Those tests are distinct from a human native-dialog/accessibility walkthrough. W37, clipboard inspection, Google account access, scheduler and background pet behavior remain disabled. The approved app-only native check was blocked by a helper capture mismatch; details and cleanup are recorded in the implementation report.

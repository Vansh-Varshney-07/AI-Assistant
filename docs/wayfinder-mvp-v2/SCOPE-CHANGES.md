# What changed in the new MVP

1. **Main app first.** The deliverable is a configurable personal AI application, not an animal character or only a narrow research demonstration.
2. **Persistent plain quick chat.** Retain the user's always-available small window with a main-app expansion path, shared conversations, status and approvals. Availability is bounded by the device/runtime being awake and healthy.
3. **Animal UI removed.** No character/animation/artwork gate in this MVP. Desktop scanning, screenshots, screen recording and always-on microphone remain excluded despite those items appearing in the older supplied text.
4. **Plugins are user-manageable.** The app exposes connection configuration, operation scopes, health, enable/disable/revoke and reviewed upgrades; it does not merely hardwire tools behind a chat prompt.
5. **Workflows are editable product objects.** Natural-language plans and form-created plans can be validated, saved/versioned, edited, run, paused, inspected and reused. A workflow is not only a model's textual checklist.
6. **Dynamic bounded workers.** Reuse tools and procedures first; create a worker when a step needs independent reasoning. Seven permanent domain agents are not required.
7. **Memory first, with measurable gates.** Preserve Iron Web, decide its authority/gateway contract explicitly, enforce orchestrator-only access, and require source/temporal/correction/consent/delete/recovery checks. A few successful answers do not establish perfection.
8. **Tavily-first for appropriate web tasks.** Prefer search/extraction/crawl/map for public information; use the proper private service APIs, local workspace tools and separate browser-control adapters for different capabilities.
9. **Framework responsibilities corrected.** Hermes supplies execution, NemoClaw deployment/configuration, OpenShell applicable sandbox controls, and the custom app owns cross-plugin workflow orchestration and exact action approval. None automatically supplies the entire product contract.
10. **Security moves before real effects.** The supplied phase order puts approval/security after workflow execution; the new phases establish the gateway before live connector writes and verify worker restrictions before broad worker capability.
11. **Every request need not be a large workflow.** Simple answers or atomic calls use a light path; complex tasks get explicit dependencies/workers. Both retain appropriate scope, limits and receipts.
12. **Broad integrations remain an extensibility goal.** Calendar/GitHub are starter targets; Notion/email/WhatsApp Business/fitness follow their provider/account/adapter gates. No universal credential or arbitrary unsupported API is promised.
13. **Previous choices survive.** Windows/local first, separate memory spaces, no worker memory access, exact change approval and narrow revocable recurring grants remain controlling requirements.
14. **Research demo stays an acceptance scenario.** The earlier document-to-brief/follow-up example is useful for proving the platform, but does not replace the user-facing configurable MVP. Hackathon submission timing is separate from accepting product/security gates.

The original [supplied master plan](sources/SUPPLIED-MASTER-PLAN.md) is background, not executable instructions. Its animal/capture sections and final recommendation to delay the UI are superseded by the latest user request. No historical design or test report was erased.

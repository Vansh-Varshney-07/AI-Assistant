## Question

Which measurable isolation, approval, sync, memory, skill and fitness checks must pass before using real accounts or calling the product ready? Decide test-account rollout, held/failed/uncertain states and user-visible recovery.

## Recommended direction — not a resolved decision

Require negative boundary tests, denied-action zero-call evidence, actual receipts, restart/reconciliation checks, numerical fitness fixtures and forgetting/restore checks. Compare Nemotron models without making them permission authorities.

## Resolution evidence

A reviewed acceptance matrix, evidence format and staged rollout/rollback checklist. Historical memory tests alone do not validate the new product.

Foundation report additions: verify account-visible Nebius models and actual runtime routing separately from earlier NVIDIA endpoint tests; test tool-result replay, streaming, cancellation and all auxiliary inference routes. Plan a 30-case synthetic evaluation, budget exhaustion, host reboot/sleep recovery, deletion-aware restore, a clean install, a synthetic public demonstration and submission/runbook evidence. Pin dependencies and record real negative sandbox tests. These remain proposed gates, not passing results. [Foundation integration](../research/foundation-report-integration.md).

## Comments

Charted, not worked. Claim before investigation. Human-in-the-loop decisions require the user's response; do not answer on their behalf.

# Proposed desktop contract v1

Design authority: wayfinder.desktop/1. These are requirements for additive integration with the existing Python service. They are not installed endpoints, grants, migrations or worker output changes. Stable wire schemas and generated TypeScript decoders are implementation deliverables; worker task/result definitions remain owned by their existing developer. Where the installed host cannot enforce a requirement, that binding is unavailable rather than silently widened.

## C01 — Canonical chat and model disclosure

Application conversation records are the display and history authority. Each request freezes authenticated owner, space, conversation, request ID, input hash, selected provider/model/profile version, bounded history message IDs and context revision. The service supplies identity; the renderer cannot assert it. Hermes receives only that frozen input through the existing managed execution path, with **R1 tools closed and automatic memory disabled**. Use a fresh bounded invocation or a demonstrated equivalent isolated session; never merge global Hermes history or duplicate canonical transcripts. If the installed Hermes path cannot exclude inherited tools/history/memory, R1 live inference is blocked.

First run explains which provider receives typed conversation text and its applicable account data policy. Provider credentials remain in the managed host. A queued request keeps its provider binding; switching the UI selector affects future requests. A policy/provider change invalidates an unsent request that no longer qualifies; dispatched data cannot be recalled. R2 disclosure must additionally pass C08/C09. No automatic model fallback that changes disclosure or cost. A missing credential opens setup instructions without asking the user to send a token in chat.

History selection is deterministic and token bounded: system policy plus permitted recent completed turns and the current input, with an explicit omitted-history indicator. Exclude failed/cancelled partial messages and stale/retracted context. R1 has no model-produced history summary cache. A conversation has one active attempt; new submissions enter the bounded queue or receive a visible busy refusal. An explicit retry selects a predecessor and a new attempt, not an automatic resend.

## C02 — Runtime identity, startup and shutdown

One runtime owns one explicitly selected app-data root. The existing runtime lock remains authoritative; a UI singleton is only a convenience. Do not copy/open live embedded stores from another process. The default root is stable across portable executable moves; switching roots requires an explicit closed-runtime flow. Do not silently create an empty replacement after an attach failure.

A host-only descriptor binds runtime ID, instance generation, app-data identity, API/schema versions, process start identity and transport. It contains no bearer secret. Owned child bootstrap uses an authenticated inherited local channel. Attaching to an already-running service requires an explicitly paired host credential and the matching descriptor. If supported secure pairing is absent, return unavailable; do not invent a port/PID-based trust fallback. Verify the selected instance on every connection; deny redirects and generic destinations. Main brokers supported intents, never a generic authenticated fetch.

Lock ownership is released only after confirmed process exit or the existing lock's safe recovery protocol. A heartbeat timeout does not permit stealing an active owner's lock. An unreachable owner produces recovery diagnostics. Never kill a PID without matching process identity and ownership. R1 may expose storage/engine prerequisites even though chat does not use memory: if the current AppService initialization needs FalkorDB, qualify it or report blocked; no hidden parallel chat store.

R1 last-window Close and Quit stop accepting **this app's** work, cancel queued work, request cancellation of active owned attempts, persist what can be persisted, and close the UI. Stop an owned backend only after a bounded drain and record interruption; never terminate a shared Hermes runtime. A shared backend may finish an already-dispatched upstream call; delivery remains fenced and possible cost is disclosed. No new work continues on behalf of a closed R1 app. R5 changes background behaviour only through C17, visibly and explicitly.

Health is per component: app API, app storage, Iron Web graph/vector availability, Hermes/model, broker, and later each connector. Show starting/ready/degraded/unavailable with safe recovery instructions. No automatic install, permission escalation, service reset, download or production-data repair. One bounded startup progress operation can be cancelled without claiming all child processes have stopped.

## C03 — Accepted requests, dispatch and deduplication

Commands carry a client-generated request ID persisted in the trusted host's local pending-command journal **before transmission**. Namespace it by authenticated owner, space and operation. Journal contains the minimum payload/hash needed for recovery under C21; it is not an alternate transcript. A first send may be observed as Sending; acceptance requires an atomic service commit of input message, request hash and run/attempt identity. If the DB commit fails or disk is full, no accepted receipt and no dispatch.

Same ID and same immutable payload return the existing attempt; changed payload under that ID is rejected. Reconnect first queries command status using the original ID. Unknown delivery never creates a new ID automatically. A trusted explicit retry is a new, linked, bounded read attempt. Automatic retries are allowed only for read observation; command retry count defaults to zero. A new request ID is not permission to duplicate an uncertain external action (C13).

Before first command admission, main obtains a service-issued command namespace valid for at most 24 hours and this runtime generation. It is a deduplication/admission envelope, not a resource grant. After its expiry/restart, old IDs may query existing status but cannot create new records, even after dedup rows have been compacted. Pending commands need user resolution, not silent minting of a fresh identity. Use C06 clock rules; namespaces from a prior runtime generation cannot admit unknown commands. This bounds replay retention without retaining message payload forever (C21).

Reserve dispatch durably before invoking Hermes/provider. Reserve then crash is conservative: interrupted/unconfirmed, even if no call happened. No automatic redispatch on restart. If a dispatcher lease expires while a worker is alive, another worker cannot redispatch the same attempt; capacity may remain occupied until observation/reconciliation. This is at-most-one **local dispatch admission per attempt**, not exactly-once provider execution. SDK/HTTP transport retries must be disabled for effects or separately qualified against provider semantics. Read inference may still incur cost after local cancellation.

## C04 — Events, reconnection, cancellation and budgets

Envelope: version, runtime ID/generation, owner-bound space/conversation/run/attempt IDs, monotonically increasing per-attempt sequence, type and bounded payload. IDs and counters are opaque/decimal strings, never rounded JS Numbers. Validate generated wire decoders, including existing Python wire boundary behaviour. Terminal snapshot and final transcript message commit atomically, or use a transactional outbox equivalent in the existing service; a final is not appended separately by each window.

Events route by immutable conversation/space/attempt, never current selection. Deduplicate by attempt and sequence; drop old generations after authenticated snapshot resync. Define cursor retention and a snapshot response for expired/gapped cursors. Bounded buffering: at most 128 out-of-order frames or 1 MiB; beyond that discard the buffer and request a snapshot, never restart execution. Cap a frame at 64 KiB; long text uses bounded chunks. Slow/hidden views can discard deltas and recover from snapshot. Each subscription has explicit unsubscribe and auth checks; no global broadcast of other spaces.

States: queued, reserved, running, stop_requested, completed, cancelled, failed, interrupted. Server compare-and-set decides races: completion committed first remains completed; authoritative cancellation first suppresses late final publication. Stop is immediately acknowledged locally but not labelled upstream-aborted without evidence. External action outcomes have a separate state machine (C13); an action can still be uncertain even if a parent run stops. A partial response is marked incomplete and excluded from default future history. Budget/concurrency reservations remain until known end, upstream deadline or explicit uncertain accounting, not just a hidden UI.

R1 draft limits: one actual model call active globally, three queued, 120-second execution deadline, selected model's published context/output limits capped by an explicit profile. Text submit limit 32 KiB UTF-8. No silent truncation; show why a request exceeds the chosen model/limit. Deadline stops admission/delivery and requests upstream cancellation; cannot guarantee termination or a hard dollar cap when usage/abort are unavailable. Foreground work reserves queue capacity before R4 background work is introduced. Unknown usage is unknown, not zero. These are initial laptop defaults, adjustable only downward within service policy until measured qualification justifies a versioned change.

## C05 — Schema, migration, build and recovery floor

Before R1: record pinned host/SDK, build Node, Electron, Python/Hermes, API/schema, Windows/WSL topology and licenses. No requirement to use the moving upstream branch or automatically upgrade the active runtime. A qualified Hermes extension is preferred only if it preserves every C01–C07 boundary; otherwise choose the thin shell. The shell and extension are alternative delivery hosts, not two product backends. Preserve the existing API's browser-Origin rejection.

Negotiate compatibility before any read/write. An unsupported schema opens only a dedicated recovery screen, not a best-effort data reader/writer. Migration is owned by one stopped/drained runtime under its lock; check disk space, create a verified supported backup, migrate transactionally where available, verify completion, then enable service. Graph/vector migration uses the existing supported backup/restore APIs and explicitly records partial state; no raw live directory copy. If an export/backup/restore cannot be qualified, that migration does not ship. An older executable alone is not a rollback; restore only compatible data in an isolated root, apply C09 deletion constraints, then deliberately switch roots. Keep originals recoverable. R1 local unpacked Windows build precedes an installer. No automatic updater; signing and distribution qualification precede sharing beyond the development machine.

## C06 — Commands and exact reviews

Use existing policy/action gate/receipts; do not replace them with a model or frontend decision. A proposal freezes exact account identity/generation, resource/version, ordered operations, parameters/payload, preconditions, evidence revision, scope, expiry and immutable digest. Only trusted authenticated user intent can approve. The review is a service-issued record, not a Markdown button. Editing creates a new proposal; it cannot mutate an already-approved digest. Approve/reject/revoke use backend compare-and-set so competing windows cannot accept two decisions.

The conversation renderer's approval IPC is a **request to review**, never sufficient authority to approve. Main reloads the exact service-issued proposal and opens a main-owned plain-text confirmation for initial small scalar memory changes; only that trusted interaction completes the decision. Reject/refuse if the full bounded payload cannot be displayed. Native dialog callback is bound to proposal digest/expiry/owner and is not exposed as a renderer-supplied confirmation flag/token. Larger later payloads require an independently qualified isolated trusted review surface with no model HTML or general conversation bridge. The inline inspector remains the readable preview. A forged renderer approval call, old review window or compromised model output cannot skip trusted confirmation. Direct reversible task forms use their scoped local-edit policy (C12), not this external/memory proposal approval path.

Revalidate at final resource admission. Revocation prevents later admission but cannot undo an effect already admitted/in flight; display the timing boundary. UI account selector changes never retarget a proposal. Disconnection/account replacement invalidates the old generation. If a provider lacks a needed conditional-write guarantee, do not promise conflict-free updates: narrow to an operation with qualified semantics or keep it disabled. Wall-clock rollback cannot lengthen an in-process approval: check wall expiry and monotonic remaining lifetime; after restart require fresh review for pending one-shot approvals. Never revive expired grants from disk.

## C07 — Rendering, IPC and source opening

Renderer is untrusted: sandbox, context isolation, no Node integration, restrictive CSP, no webview/generic IPC, no bearer tokens. Validate originating top frame and schema in main and validate authority again in Python. Package-resource URLs only for app navigation; deny unexpected popups/permissions/navigation. No model HTML, active SVG, executable Mermaid, script/event handlers or embedded remote page. Sanitized Markdown/code is text; copy buttons copy only selected displayed text following user intent, never inspect the clipboard. Remote images are off by default. The preview's inline-script CSP is an offline prototype exception, never production policy.

Model/source text cannot become an app deep link, file opener, shell argument or approval. Ordinary outbound HTTPS links require explicit click, a validated URL with visible destination, no embedded credentials/control characters, and an external-browser handoff; disallow file/data/javascript/custom schemes and localhost/private-network navigation. Do not fetch link previews or follow model redirects automatically. Backend citation IDs resolve through current scoped policy; historical retained evidence is distinguished from re-reading a changed source. Renderer content is not inserted as raw untrusted innerHTML. DoS limits include bounded Markdown size/nesting/code rendering and lazy long-history rendering; preserve incomplete/truncated indicators and access to the full permitted artifact through a bounded viewer.

## C08 — Selected documents, citations and disclosure

Use the current scoped file broker and Hermes/W35 parsers; add policy integration, not another parser or desktop driver. R2 initially advertises only formats and extraction methods demonstrated in the installed binding, starting with UTF-8 .txt/.md fixtures. No unsupported PDF/OCR/archive promise. Draft limits: 3 selected files, 5 MiB each, 10 MiB per request, 100,000 extracted characters total, further bounded by model/context policy. Refuse a limit violation before transmission or offer an explicitly reviewed excerpt, never a hidden complete-file claim.

The trusted picker issues a narrow selection reference. Re-resolve path identity, final handle/target, granted root, hash and byte length at access; block junction/symlink escape, device/UNC paths and changed/locked/unreadable inputs unless separately supported and authorized. Do not accept an arbitrary renderer-provided path. Reading and provider disclosure are distinct checks. Show provider and selected file names plus the existing approved data-class policy; an existing compatible grant does not require repetitive prompts. A blocked disclosure requires choosing an allowed provider or excerpt, not falling back remotely.

Snapshot selected evidence into bounded task-scoped artifacts only through the existing service. Track source identity/version, observed time, extracted-range coverage and parse warnings. Temporary local/sandbox copies are purged at task retention expiry or explicit deletion; cleanup failure remains a visible pending obligation. Revocation prevents further access/delivery but cannot retract bytes already sent to a provider. A historical citation can show its permitted retained excerpt with its original hash/time; current-source opening needs a fresh permitted selection/access check and labels changed/unavailable content. Do not silently refresh an old citation into new evidence or broaden file access.

## C09 — Memory correctness, correction, forget and restore

Keep the orchestrator-only Iron Web gateway and existing source/claim lifecycle, storage, conflict and maintenance APIs. Workers receive bounded packets, never credentials/direct store access. Explicit Remember/Correct/Retract proposes a scoped change and uses C06; do not create free-form model writes or another memory engine. Correction preserves attributed history and changes current recall; dispute stays disputed; maintenance is dry-run/review-first and scoped. Define the canonical prose-to-fact schema through the gateway, not by changing worker-owned contracts.

Expose three distinct actions: retract a claim from current recall; forget selected durable memory and its derived context; delete a conversation's local content. Do not label any of these universal provider/backup erasure. A forget request reserves a privacy barrier durably **before** purging graph/vector/cache copies. Bump the affected space's context epoch; withhold dependent pending outputs/proposals; invalidate packets and projections. If lineage is incomplete, conservatively invalidate all derived context in that space. Revocation/correction also revalidate applicable pending actions at final admission.

To prevent untracked paraphrases re-entering a prompt, after a forget barrier every pre-barrier conversation in that space is view-only for inference; a new conversation begins with no previous turns. The UI explains this cost and offers a new chat. Current gateway evidence must be rebuilt under the new epoch. Old visible history is labelled historical and excluded from new prompts; deleting it is a separate selectable purge. A user deliberately re-entering information or a newly selected independent source is new input, not proof of a purged-source resurrection; future retention still needs consent. In-flight provider disclosure cannot be undone, but stale late output is not published as current.

Purge completion requires the existing memory API's acknowledged results across all declared active stores/artifacts; partial graph/vector cleanup remains privacy-blocked and reported pending, with no memory retrieval in the affected space until verified. No completion receipt on partial failure. Minimal opaque deletion IDs/epochs remain in a protected deletion ledger; no plaintext fact or unsalted content hash in its tombstone. Restoring old backups occurs offline in an isolated root and applies the **latest** ledger before any retrieval. If the latest ledger is missing or cannot be verified, refuse activation; a user may deliberately inspect/export quarantined content through a separate warned recovery workflow, not normal memory recall. Backups retain deleted material until separately expired/deleted; external/provider retention is outside a local forget receipt.

## C10 — Memory release evidence

Retain the earlier [memory-quality contract](../wayfinder-mvp-v2/MEMORY-QUALITY-CONTRACT.md). Proposed R2 gate: all deterministic scope/durability/consent/deletion/restart invariants pass, with zero observed unauthorized access, false saves, source fabrication or forgotten-source resurrection. Pre-register 40 held-out answer cases: 20 straightforward, 10 paraphrase/context-selection and 10 missing/disputed/historical; target at least 38/40 case-correct outcomes with attributable expected sources and correct abstention. These are proposed release thresholds, not observed results or general reliability claims.

Freeze suite, expected outputs, model/profile/version, neural embedding path and scope before running the held-out evaluation; separate tuning fixtures. Report per-case failures, retrieval precision/coverage, stale/current errors, cross-space probes, latency and actual/unknown cost. Deterministic test embeddings validate plumbing, not neural retrieval. A mock worker, one live model run or a successful storage write cannot substitute for the scoped neural evaluation. Block the affected R2 feature if required invariants fail; earlier accepted R1 may still ship under C23.

## C11 — Google account and read lifecycle

R3 core qualifies Calendar/Tasks reads and Gmail **references only**, through existing fixed read adapters and supported Google OAuth libraries. No body fetching, sending, arbitrary URL tools or token access in workers. Pin actual scopes, endpoints, projected fields and page/byte bounds per operation; disclose a partial page/result. Calendar queries display the selected IANA zone and observed range; provider reads at different times are not an atomic snapshot. Source content is untrusted evidence, never instructions. Offline cached data is labelled with observation time and may not support a fresh brief without explicit freshness policy.

Connection status separates configured, authenticated account identity, requested/granted scopes, operation qualification, current resource authorization and health. OAuth consent is not an action approval. Reuse a supported desktop account-consent flow; no new OAuth server/credential store. Live account setup is a later human step with provider credentials saved outside Git; no passwords/tokens in chat. Provider consent/browser use is not performed during this planning task. If the installed client/library/redirect mechanism cannot be qualified, the connection stays unavailable.

Bind every read and pending proposal to immutable provider account ID plus connection generation. UI selection alone cannot substitute accounts. Re-authentication verifies account and scopes; replacement/disconnect/revocation bumps generation, revokes local grants, blocks new dispatch and suppresses old-generation late delivery/current cache use. Do not claim an already-dispatched provider read was undone. Local historical excerpts have their explicit C21 retention and are unavailable for fresh context until reauthorized. Transient network loss does not itself replace identity; show retryable health while retaining conservative access checks.

Controls are distinct: Disable stops app use; Disconnect invalidates local connection/grants and removes local token; Revoke provider consent invokes a separately explicit supported revocation flow and verifies/report uncertainty; none deletes Google data. Pending/unknown external effects retain minimal C13 records. Token expiry/scope loss opens Needs consent with the affected account, not an infinite refresh/retry loop. A read retry is bounded (at most 3 attempts total, deadline/budget permitting, provider Retry-After respected); invalid credentials/scope/account are not retried automatically. Rate-limits and provider outages preserve a labelled last-observed view without claiming it current. Active-view changes cannot route late data into another space.

## C12 — Local tasks and provider tasks stay separate

R3 has a small durable WorkItem layer in existing application storage: opaque ID, owner/space, title, optional date-only due_date, state pending/completed, local version, created/updated times and deletion marker. No reminder execution or durable memory promotion implicit in a task. Direct user edits use a trusted scoped form/checkbox intent with exact target/version and service validation; a model-proposed change uses C06 review. Reversible direct edits need not add a redundant approval dialog when the exact effect is already visible. Concurrent stale edits return a conflict and refresh the item; no last-writer overwrite without user choice.

Google Tasks entries remain read-only provider projections with separate account/list/task IDs, raw status, canonical displayed state, provider updated/version fields when available, observed time and tombstone/missing state. Explicitly map needsAction to pending and completed to completed in the projection adapter; unknown states display unsupported, not silently pending. Retain raw/version data for attribution, without claiming current provider conditional writes are qualified. Date-only due values are rendered as calendar dates without timezone conversion; timed reminders are a different operation. Notes are untrusted text and do not become commands.

No R3 two-way sync, automatic import, auto-complete mirroring, or writeback. A local task and a provider task can look alike without being linked. An explicit Copy to local creates a new draft with a source reference and a clear one-time-copy label; editing/completing/deleting it changes only local storage. Refresh does not resurrect a deleted local item or overwrite a local title. Provider disappearance is shown as missing in its own view, not a local deletion. Two-way synchronization is **deferred**, not a hidden future service assumed by other releases; it requires a separate conflict/version/identity design before adoption.

## C13 — Optional external effects and uncertainty

R3 through R6 core are external read-only; approved memory/local task changes are internal scoped writes. Google writes, Gmail sending and coding/native effects are separate R7 optional operation modules, default off. A module must identify one exact operation and provider contract rather than enable a whole connector's writes. No generic adapter becomes qualified by sharing an approval card.

Per operation freeze input/account/resource/version, dispatch admission rule, provider idempotency/conditional-write support, SDK retry behaviour, receipt fields, independent verification method, attribution rules and reconciliation grant. C06 covers authority; C03 covers local admission. Provider acknowledgement alone is acknowledged, not independently verified. States: proposed, rejected/expired/revoked before admission; reserved/dispatched; acknowledged; verified; failed_no_effect only with evidence; otherwise uncertain. Stop/revocation after dispatch never becomes proof of no effect. Record these outcomes independently of parent chat cancellation.

Lost response, timeout, crash after reservation, weak attribution or ambiguous provider search stays uncertain. Show Result needs checking, no ordinary Retry. Fresh read-only reconciliation needs its own current narrow authorization, independent provider ID/operation correlation and evidence; a similar-looking item is not proof. Reconciliation cannot mint a resource grant or issue another write. If the user disconnects/deletes needed evidence, show unresolved and preserve a minimal duplicate lock. Where a provider cannot support trustworthy attribution, keep the module unavailable or disclose that uncertainty cannot be resolved automatically; never call this exactly-once.

A new command ID, new window, edited title or parent workflow retry cannot bypass an unresolved attempt. Service maintains an operation/resource duplicate-risk lock keyed to the reviewed semantic action and **stable provider account identity**, not the transient connection generation. Generation fences authorization; reconnecting the same account must still see its unresolved effects. Different account selection is not reconciliation. A user may explicitly abandon tracking, but that does not assert no effect or automatically unlock a duplicate operation; any intentional repeat needs a separately qualified risk-review operation, excluded from initial R7. No broad permanent account lock: unrelated qualified resources/operation families can proceed under their own scope, and a read-only status path remains available. Exact semantic-lock boundaries must be operation-specific and tested before module qualification.

Default initial-module lock is the conservative stable account/resource/operation family; a different title/request ID is not proof of an independent action. An adapter may narrow only with demonstrated independent stable resource/operation identity, never fuzzy model judgement. Thus another create in the same list may remain blocked while unrelated resource/family reads or operations remain possible. This is a visible recovery restriction, not a claim of perfect semantic equivalence detection.

If explicit content deletion removes a narrower semantic key/evidence, do not retain a hidden content-derived digest just to preserve the lock. Widen that unresolved marker to its stable account/resource/operation family, explain the restriction, and leave other families/resources available. Same-family creates can stay blocked until attributed reconciliation; initial R7 has no automatic or unreviewed unlock. If an operation cannot tolerate this privacy/recovery tradeoff, do not qualify it. Local deletion must not pretend it preserved fine-grained reconciliation without the required evidence.

## C14 — Small versioned workflows

R4 is a bounded **linear step list**, not an arbitrary DAG editor, agent framework or replacement delegation loop. Initial catalog: Calendar read, Tasks read and scoped brief synthesis using existing qualified worker bindings. At most 6 steps, dependencies only on declared earlier steps; no loops, nested workflow calls, autonomous spawning or external writes. Save supported inputs and resource intentions, never credential material or an expiring grant/ticket. A disabled operation cannot enter via import/raw JSON.

Validate template schema/version, allowed step kinds, required inputs, exact input/output types and references, release qualification and aggregate limits before save/run. Pin a template and capability/skill version per run. An edit produces a new version for future runs; active runs remain bound. A newly disabled/revoked binding blocks its next step even though version is pinned. Do not silently upgrade to a newer skill/provider. Existing worker task/result contracts are consumed through adapters, not rewritten by the UI.

Each edge carries source IDs/versions, observed-at times, coverage, context epoch, disclosure restrictions and freshness deadline. Synthesis validates them immediately before transmission; source revision changes withhold output or create an explicit new read attempt within fresh authorized scope. First recipe freshness budget: 5 minutes for Calendar/Tasks observations, no silent cached substitute. All initial steps are required: a failed/denied/malformed/missing/expired input stops dependent synthesis and preserves a labelled partial run. A later optional-input recipe needs an explicit version and expected partial-output schema, not a model guess. Two manual starts have two linked run identities; duplicate delivery of one start has one run.

## C15 — Run-tree admission, budgets and fresh grants

Manual workflow review binds versioned read resource intentions, space/account generations, execution/disclosure policy, deadline and maximum work. It authorizes only this run. The service issues fresh short-lived worker/context references within that valid authority and revalidates before each use; it cannot extend the overall run right. Expired task authority requires a new user decision, not automatic renewal. Workers never issue their own grants. C17 adds a separate standing authorization for future occurrences.

Initial aggregate limits: at most 6 steps, 2 model calls, 3 total attempts per retryable provider read, 10-minute run deadline and 1 actual model call active globally. No nested autonomous delegation in R4–R6; existing Hermes/WorkerHub routing executes bounded selected roles only. Count descendants, reads, retries and pending calls against the root, not each worker independently. Reserve bounded tokens before each model call using the pinned profile; reject if the provider cannot expose/enforce needed output bounds. Monetary cost is informative/unknown unless a provider contract supplies an enforceable spend limit. Do not advertise a hard dollar cap from an estimate.

One active background workflow and one queued background occurrence at most. Foreground queue is separate, bounded to 3 as in C04, and takes the next available model slot before queued background work. An in-flight background model call is not silently preempted; show queued/remaining deadline. No foreground starvation guarantee beyond this finite queue policy. Cancelling root prevents new children, marks queued children cancelled, requests upstream stop and preserves pending-effect/cost accounting until confirmed or classified uncertain. Restart marks reserved/in-flight work interrupted and resumes observation only. Initial recovery is **inspect and explicitly start a new read run**, not resume a half-executed workflow. Reusing earlier evidence requires current authority/epoch/freshness and an explicit new run reference; completed external effects are never replayed as recovery.

## C16 — Scheduler semantics, deliberately narrow

Initial R5 schedule is one read-only saved brief, **daily at an explicit local time in a fixed IANA timezone**. No arbitrary cron UI, follow-device timezone, automatic time-zone travel, catch-up burst or background write. Show the next UTC instant plus local date/time/zone before approval. DST policy: a nonexistent local time is skipped with a visible reason; a repeated local time uses the first occurrence only. Laptop sleep/offline/missed deadline: skip, no catch-up. Maximum lateness 60 seconds; a past occurrence is not executed on reconnect. No overlap: if that schedule's previous occurrence is still active/uncertain, skip the new occurrence and explain. Pausing stops future admission; cancel-active is a separate explicit operation.

Use the installed Hermes scheduling facility, qualified against these semantics. The Wayfinder adapter validates/records intended instants and admissions; it does not invent another timer/cron executor. If Hermes cannot reliably implement fixed-zone gap/fold/skip semantics and bounded delivery, R5 recurrence does not ship. Tests need real adapter evidence as well as timezone arithmetic. Changing OS clock/timezone does not rewrite an existing fixed-zone schedule; backward clock jumps cannot readmit a recorded occurrence.

Occurrence identity is schedule ID plus intended UTC instant, with unique durable admission. Bind schedule revision, template/binding version, account generation and standing authorization to that occurrence. Late callbacks from old revisions cannot admit work. Edits default effective next local day to avoid a second same-day run; show the effective instant. Resume covers future occurrences only. Retain admission tombstones beyond maximum accepted callback lateness; old revisions/retired callback credentials cannot create new admissions after compaction or restart. Any future catch-up/second-fold rule requires a new explicit contract and acceptance, not a UI-only switch.

## C17 — Standing read authority and trusted scheduler dispatch

Store a versioned standing read authorization, **not** a one-shot approval ID or a temporary context ticket: authenticated owner/space, selected resources and account generations, pinned template/operations, disclosure policy, per-occurrence/aggregate limits, validity interval and revocation state. Initial duration at most 30 days, visibly renewable; each instance remains subject to current policy/qualification. Schedule edits to payload/resource/time/zone/policy need a fresh reviewed authorization. A revocation prevents future admission; in-flight work follows C04/C11 rather than pretending it was undone. Recheck immediately before each child resource/model access.

Hermes calls only a fixed trusted Wayfinder scheduling adapter entry with authenticated occurrence identity; it cannot run the stored prompt through inherited broad tools. Registration and callbacks are scoped to this app/schedule and paired runtime, and contain no worker-readable storage credentials. If backend/policy/authentication is unavailable, callback records a blocked/missed observation or fails closed; no unrestricted fallback. Duplicate callbacks converge on the unique occurrence record. Test the installed callback route; documentation and a cron fixture do not prove it works.

R5 defaults background OFF. Explicit enabling explains which schedules continue after closing the UI, their authority expiry and the laptop-awake requirement. Last-window close then leaves a visible tray entry; Quit Wayfinder stops this app's new admissions, cancels queued occurrences, requests active cancellation, persists state and detaches/stops only owned components. It does not kill shared Hermes. Standing schedules can resume only after a trusted app-owned scheduling component is explicitly restarted; a stale shared-host callback is denied by the disabled app admission epoch. That epoch must persist before showing Quit complete; disk failure opens a cannot-confirm-stop status and disables callbacks via the supported adapter where possible, without claiming unseen external work stopped. If this stop fence cannot be qualified, background mode remains unavailable.

## C18 — Skills, agents and configuration versions

R6 exposes actual installed worker/skill bindings through Atlas, not new prompts or permanent agent processes. Maintain immutable binding ID/version, worker role/alias, task/result contract, effective tools, input kinds, permissions, model policy, dependencies, qualification evidence/version/date and owner. Resolve one registry fragment integration path. Planned metadata alone is never Available. Availability requires release inclusion, configured binding, matching qualification and current scope/resources; a tested fixture badge is distinct from live qualification.

A configuration edit is a new draft version; inspect diff, effective-tool/egress change and dependent workflows, validate and test synthetically, then explicitly publish within service limits. A skill cannot approve its own new rights. Capability permission increases invalidate relevant pending proposals and future occurrence authorizations; active pinned work is revalidated and blocked when needed. Installed/pinned old versions are used only while policy still allows them. Imported skills/plugins are untrusted; no automatic install or install hook execution from a model. Plugin acquisition/OS permission changes are separate human setup, not a general worker tool.

Rollback selects a previously qualified compatible version for future work. It never undoes external effects, resurrects revoked grants, restores deleted content or retargets a live run. If the old version cannot coexist with current API/schema, show unavailable rather than downgrade the runtime. Disabling a role blocks new/next dependent steps, requests appropriate cancellation and keeps historical receipts. Worker prompts/output contracts remain with their developer; this layer supplies the versioned adapters and synthetic fixtures only.

## C19 — Quick access is a view, not another runtime

R5 quick chat is a second view on the same broker/service/conversation/run identity, not a new database/model session. Subscription ownership and cleanup are explicit (C04). Do not persist raw drafts in renderer localStorage. A main-held draft has a revision and one composing-window lease; a second window opens it read-only or explicitly takes over, so two sends cannot accidentally submit the same draft under different IDs. The service's one-active-attempt-per-conversation rule and C03 request identity remain authoritative. Closing a quick view releases only its view/draft lease, not shared work.

Hotkey registration is opt-in and reports conflicts without replacing OS/other-app bindings. Tray/menu always offers restore/reset; saved bounds are clamped to available displays with a readable minimum after monitor removal/DPI changes. No mandatory always-on-top behaviour. Closing/minimizing/last-window close/Quit are labelled consistently with C02/C17. Notifications are minimal by default, reveal no private message body on the lock screen, and route through authenticated internal run IDs; a notification cannot approve an action or invoke an arbitrary URL.

## C22 — Progressive UX and preview contract

Use one release/capability manifest for navigation, inspector tabs, examples, attachment controls, commands, shortcuts, import validation and API admission. A shipped feature appears only when its release and advertised variant include it; actual execution additionally requires operation qualification and current authorization. Available UI never confers authority. Historical runs from a later supported feature may be inspected read-only with a disabled-capability explanation, not replayed. An incompatible schema is still C05 recovery-only, not a reason to render unsupported records.

R1: Chat, Runs, Settings; inspector is a run summary, not Google/task approval. R2: memory/document examples and service-issued memory review; R3 adds Google reads and local task proposals. No synthetic Google write or native success badge. Default preview opens R1. Switching the design release normalizes route/tab before rendering and resets only feature-invalid state. Production capability invalidation updates controls from service snapshots, not only client filters. Offline prototype controls always announce no effect and retain no input across reload.

One actual inspector visibility state controls wide grid and narrow sheet, with matching label/aria-expanded. On narrow widths a navigation drawer has a real opener, close control, Escape and focus restore. Use a native modal dialog where supported for the **offline preview**; production accessible primitives must provide focus trapping/inert background, names and dismissal behaviour without two simultaneous modal layers. Opening one sheet/drawer closes the other; release/route changes close obsolete overlays. At wide widths the inspector is non-modal and may stay open. At every breakpoint all active destinations remain reachable.

Rerendering controls must preserve logical focus: after inspector-button replacement, focus the newly selected visible control; if a dialog's original trigger was removed, restore to the live navigation/details opener. Avoid body focus or a detached-node focus request. Handler-level tests check intent; actual native dialog, keyboard and screen-reader focus still need rendered evidence.

Composer handles compositionstart/compositionend, isComposing and relevant composition key states; Enter submits only after composition, Shift+Enter adds a line. Do not hijack Enter on another control. Visible focus remains in forced-colour mode; labelled tabs/buttons, status text and live announcements do not rely on colour. Test at 1280x800 and 1920x1080, a 600px narrow viewport, 100/125/150% DPI, keyboard-only, screen reader, IME and long content. Resize closes/re-homes modal content without losing selected route/review. The preview harness can verify handlers/state/source rules; only a real rendered walkthrough establishes layout/focus/screen-reader quality.

## C23 — Release variants and acceptance discipline

Core R1–R7 are cumulative sets in manifest.json. Each delivered version declares exact features, operations, versions, required prerequisites and optional modules. All earlier **applicable** core acceptance remains required. A later feature's failure blocks that release/module, not an already accepted earlier binary, unless it exposes a shared safety regression; then stop expansion and fix the affected baseline. Never relabel an originally required advertised feature Optional to obtain a pass. A smaller deliberately renamed variant must remove its promises/surfaces and declare a new acceptance set before evaluation.

ACCEPTANCE.csv gives unique case ID, provenance/finding, earliest release, feature/variant applicability, requirement, exact scenario/expected outcome, owner, evidence tier and status. Required cases may be Pass/Fail/Blocked/Not run; N/A requires a declared exclusion or absent optional module plus written reason. Read-only R3 excludes Google writes but must pass tests that write controls/handlers are denied. An R7 core build can omit native/communication modules; a build advertising them must run their real provider/native cases. Fixture, model, contract, packaged UI, live model, live provider and native evidence cannot substitute for one another.

Each accepted release has a Windows-launchable build, measured compatibility matrix, start/stop instructions, short ordinary-user walkthrough, redacted actual evidence, data migration/recovery support and known limits. Source syntax/static/model checks are not app acceptance. Performance budgets are measured on the user's laptop: target local submit/stop acknowledgement <250 ms and cached conversation open <500 ms; report p50/p95 plus cold-start/idle resources, without treating model latency as UI delay. If metrics are unavailable, say unmeasured. Accessibility/manual evidence is required even when headless checks pass.

For redesign checks: close findings one by one in REMEDIATIONS.csv, attach exact contract/cases and repeat old models/source hashes after every batch. Add second-order risks rather than deleting a failed case. All current implementation acceptance remains Not run. External setup steps are a dependency list, not permission to install/connect/capture during planning.

## C20 — Worker inventory, deferred families and R7 scope

Keep all W01–W47 IDs in one coverage inventory. Existing supplied names are used only where established; unresolved numbered role/alias contracts are explicitly unresolved and unavailable, not invented. A full catalogue reconciliation is an R6 release prerequisite for the advertised catalogue, not a request to recreate those agents. Each capability must map to an existing concrete binding/version or be labelled planned/deferred/unsupported. A missing number cannot be fixed with an unreviewed prompt or a green metadata badge.

Web research/source verification and external knowledge/notes connectors are explicitly **deferred** from core R1–R7, despite their planned worker families. Ordinary model general-knowledge chat is not live web research. Selected local documents are supported R2 evidence, not a notes-platform integration. A later read-only research slice needs actual provider selection, egress/query policy, source-fetch/SSRF limits, citation verification and tests. Fitness remains deferred by user choice; no vendor chosen.

W33 selected screenshot input and W36/W37 native actions are separately optional and **disabled**. ## C21 — Retention, quotas, privacy and storage failure

Keep distinct storage classes: application transcripts/drafts; Iron Web facts; immutable minimal run/action metadata; temporary context/artifacts; logs; credentials; backups. Use current storage APIs. Do not claim OS account encryption, multi-user access control or full-disk secure erasure unless independently provided; R1 assumes a trusted local OS account. Credentials stay in the established private runtime, never UI stores/export/logs/Git.

Initial local policy: transcripts and explicit memory until user deletes; drafts until cleared; task/context artifacts 24 hours after terminal outcome unless the user explicitly retains a cited excerpt; redacted diagnostic logs 7 days/10 MiB; content-free receipts/dedup metadata 30 days, then compaction. A retained citation excerpt has transcript retention and is listed in that deletion scope. Unknown action records and duplicate-prevention markers are not discarded merely on that timer; they stay minimal until resolved. Deletion barriers/epochs stay as long as any restorable backup can contain the affected sources. Quotas apply to active content before accepting new input; no automatic destruction of unresolved receipts, memory or conversations to free space. Draft app-owned content quota: 250 MiB soft warning, 500 MiB admission stop; existing graph/vector capacity has a separate displayed limit and health check. Measure actual storage before changing defaults.

Host pending-command journal removes payload after durable server reconciliation, retains only status identity while needed, and obeys explicit chat deletion. C03 retired namespaces prevent an old pruned command becoming new. Disk-full/permission failures mean unsaved/not accepted, with a bounded in-memory draft and optional user-directed export; never report a durable save from UI optimism. Do not log raw prompts, OAuth material or file contents by default. Redacted support export has an explicit preview and excludes credentials/raw artifacts unless individually selected and permitted.

Deleting a conversation first blocks further publication and marks content inaccessible, then purges local replicas, attachments, queued journal payloads and derived caches with a tracked receipt. Uncertain external action metadata retains only the minimum account/operation references needed to reconcile, not deleted prose. If the provider requires payload content for attribution and deletion removes it, retain uncertainty and disable replay rather than secretly preserving the deleted payload. Restart/recovery applies pending privacy barriers before ordinary reads. Exported files and independent backups are disclosed limitations, not silently deleted. No external account write is performed by a local delete control.

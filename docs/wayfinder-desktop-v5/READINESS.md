## Planning decision record

1. Use the GitHub design as the visual source, not as a production backend or authority model.
2. Reuse the existing thin Electron host and application services as the implementation candidate. Do not add a web proxy/server or second backend merely to preserve prototype fetch calls.
3. Start with a frozen, reviewed source assembly and new-design parity milestone. Then meet the unchanged core R1–R7 gates; do not call the current workspace ordinary chat.
4. Keep unknown role mappings, unqualified providers/scheduler/native paths and omitted destinations explicit. No UI-driven replacement agents, parsers, memory engines or schedulers.
5. Planning only until a later implementation instruction. No main merge, account setup or native testing follows automatically from this document.
